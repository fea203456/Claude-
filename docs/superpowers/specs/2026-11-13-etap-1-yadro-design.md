# Этап 1: ядро игры — дизайн

Часть игры «Увядающий край» (общая спека: `docs/superpowers/specs/2026-11-13-uvyadayushchiy-krai-design.md`). Опирается на этап 0 (`docs/superpowers/plans/2026-11-13-etap-0-konveyer-npc.md`): Godot 4.5.1 Forward+, ассеты из headless Blender, тест-раннер `game/tests/run_tests.gd`, витрина `game/scenes/dev/npc_showcase.tscn`.

Статус: согласовано с автором 2026-11-13. **[решение Claude]** — выбор без явного согласования.

## 1. Зачем

Каркас, на котором держатся все будущие системы (ферма, NPC, ночь): общее игровое время, управляемый герой, камера и сохранения, которые переживают обновления. После этапа игрок впервые *играет*, а не смотрит витрину.

## 2. Цели / не-цели / анти-цели

**Цели**
- Игрок управляет героем на тестовом участке, видит смену дня и ночи, ложится спать, выходит из игры и продолжает с того же места.
- Системы времени и сохранений — общие сервисы, к которым будущие системы подключаются без правки ядра.

**Не-цели**
- Ферма, инвентарь, NPC-распорядки, бой, Порча, меню настроек, несколько слотов сохранений, локализация UI (кроме того, что тексты идут через ключи).
- Настоящие модели героя (2 базовых тела) — отдельный этап.

**Анти-цели**
- Сохранение, которое ломается или молча теряет данные после обновления.
- Управление, которое «плывёт» относительно камеры после её поворота.
- Время, которое зависит от FPS.

## 3. Подходы (сохранения)

| Подход | Плюсы | Минусы |
|---|---|---|
| **JSON-файл + номер версии + цепочка миграций (выбрано)** | Читаемо, диффится, миграции явные и тестируемые | Сериализацию пишем сами |
| Godot `Resource` (.tres/.res) | Готово «из коробки» | Ломается при переименовании классов/свойств между обновлениями |
| ConfigFile | Просто | Плохо для вложенных данных |

## 4. Решения

### Время и календарь
- Сутки = **20 реальных минут** при скорости 1×: время идёт равномерно, **1 игровая минута = 1 реальная секунда**; активная часть суток 06:00–02:00 (20 игровых часов): день 06:00–20:00 = 14 мин, ночь 20:00–02:00 = 6 мин. Часы 02:00–06:00 пропускаются (сон или обморок).
- Время хранится как целое число **игровых минут от начала суток** + номер дня; продвижение по `delta` реального времени, не по кадрам.
- В **02:00** без сна → «обморок»: переход на 06:00 следующего дня в доме, штраф (на этапе 1 — флаг `collapsed_last_night = true`, поведение штрафа — позже).
- Сон в кровати в любое время после 18:00 → 06:00 следующего дня, автосохранение. **[решение Claude: спать можно с 18:00]**
- Календарь: 4 сезона × 28 дней (Весна, Лето, Осень, Зима), дальше год+1.
- События для подписчиков: `minute_changed`, `hour_changed`, `day_started`, `night_started` (20:00), `season_changed`.
- Скорость времени настраиваема (для тестов и отладки), пауза при открытом меню.

### Освещение по времени
- Цикл солнца: угол и цвет DirectionalLight, энергия ambient, цвет неба и плотность/цвет объёмного тумана интерполируются по ключевым точкам суток (рассвет 06:00, день 12:00, закат 19:00, ночь 21:00+). Ночью туман гуще и холоднее. Значения — в одном ресурсе-кривой, чтобы художественно настраивать без кода.

### Управление
- Действия Input Map: `move_forward/back/left/right` (WASD + левый стик), `run` (Shift / L-триггер или кнопка стика), `interact` (E / кнопка A-South), `camera_rotate_left/right` (Q/R / плечевые кнопки), `camera_zoom_in/out` (колесо / D-pad вверх-вниз), `pause` (Esc / Start).
- Движение относительно текущего угла камеры; скорость шага 1.4 м/с (совпадает с шагом анимации), бег ×1.8 **[решение Claude]**; анимация Walk проигрывается со скоростью, пропорциональной фактической скорости; Idle при остановке.
- Герой — `CharacterBody3D` с коллизией; не проходит сквозь дом и частокол.
- Взаимодействие: ближайший объект-«интерактив» в радиусе 1.5 м перед героем, подсказка над ним («E — лечь спать»).

### Камера
- Изометрический ракурс 45° вниз, следует за героем с плавным догоном.
- Поворот вокруг героя шагами по 45° с плавным доворотом (~0.25 с).
- Зум: расстояние 6–14 м, по умолчанию 8 м.

### Сохранения
- Один файл `user://save/slot_1.json` **[решение Claude: один слот на этапе 1]**.
- Формат: `{ "save_version": N, "game_version": "...", "time": {...}, "player": {...}, ... }`. Каждая система отдаёт и принимает свой раздел (реестр «сохраняемых»), ядро не знает их внутренностей.
- Миграции: функции `vN → vN+1`, применяются цепочкой при загрузке старого файла. Файл новее, чем знает игра → отказ загрузки с понятным сообщением, файл не трогается.
- Запись атомарная: во временный файл, затем переименование; предыдущее сохранение хранится как `.bak`.
- Автосохранение — при сне и при обмороке. Ручного сохранения на этапе 1 нет; при выходе из игры — сохранение.
- Повреждённый файл → загрузка из `.bak`, иначе новая игра с предупреждением.

### Тестовый участок
- Новая основная сцена: земля у края тумана (~40×40 м), дом-заглушка (простой блок с дверным проёмом, собран в Blender из палитры), кровать внутри, частокол по краю, туман за частоколом.
- Старт новой игры: день 1 Весны, 06:00, герой у дома.
- Минимальный HUD: время, день и сезон в углу; подсказка взаимодействия.
- Главное меню на этапе 1: «Продолжить» (если есть сохранение) / «Новая игра» / «Выход».

### Уточнения после проверки
- **Выход из игры сохраняет полный снимок:** позиция и поворот героя, точное время и день, угол и зум камеры. «Продолжить» восстанавливает ровно это (согласовано: «продолжить с того же места»).
- **Множитель скорости** (отладка/тесты) умножает ход времени равномерно.
- **Кровать до 18:00** показывает подсказку «Ещё рано спать» и не срабатывает. Интерактивы имеют `can_interact()` и подсказку, зависящую от состояния **[решение Claude]**.
- **Пауза (Esc/Start):** простое меню паузы «Продолжить / Выйти в главное меню» (с сохранением). Время на паузе и в меню стоит; обморок в 02:00 не может случиться на паузе **[решение Claude]**.
- **Геймпад** — обязателен в Input Map, проверяется тестом на наличие привязок; ручная проверка геймпадом — у автора **[решение Claude]**.
- **Свет:** автоматически проверяется, что средняя яркость кадра упорядочена: день > закат > ночь; плюс 4 скриншота (06:00, 12:00, 19:00, 23:00) для глаза **[решение Claude]**.
- **Коллизии дома** — набор простых коробок, расставленных вручную **[решение Claude]**.

## 5. Что остаётся на разработчика
- Точные кривые света и тумана (настроить на глаз, проверить скриншотами утро/день/закат/ночь).
- Внутренняя архитектура: какие узлы autoload, как устроен реестр сохраняемых.
- Вёрстка HUD и меню (минимальная, без художественного оформления).
- Форма и размеры дома-заглушки.
